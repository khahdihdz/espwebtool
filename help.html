Nạp firmware lần đầu

  1. Cắm ESP32 DevKit V1 vào điện thoại Android bằng cáp USB OTG (USB-A ⇄ USB-C/Micro-USB tuỳ điện thoại).
  2. Mở trang này bằng Chrome for Android (hoặc trình duyệt Chromium khác — xem trang Kiểm tra).
  3. Vào trang Flash, bấm Kết nối ESP32.
  4. Android sẽ hỏi quyền truy cập USB — chọn đúng thiết bị CP2102/CH340 rồi bấm Kết nối.
  5. Nếu không nhận được: giữ BOOT → nhấn RESET/EN → thả RESET/EN → thả BOOT → thử kết nối lại.
  6. Chọn file firmware.bin (offset mặc định 0x10000).
  7. Bấm Flash Firmware và chờ tới khi log báo SUCCESS và ô Verify hiện VERIFY SUCCESS.

Cập nhật qua OTA (không cần USB)

  1. Sau lần flash đầu, ESP32 tự tạo AP ESP32-SETUP nếu chưa có Wi-Fi đã lưu.
  2. Kết nối điện thoại vào AP đó, nhập SSID/mật khẩu Wi-Fi nhà bạn qua trang cấu hình của firmware.
  3. Mở trang OTA, nhập URL manifest.json (thường host trên GitHub Releases).
  4. Nếu có bản mới, thiết bị (không phải trang web) sẽ tự tải, kiểm tra SHA-256, ghi vào OTA partition rồi khởi động lại.

Xử lý lỗi thường gặp

Không tìm thấy thiết bị

Kiểm tra: cáp USB OTG có hỗ trợ truyền dữ liệu (không phải cáp chỉ sạc), đã cấp quyền USB khi trình duyệt hỏi, và cáp/cổng không lỏng.

ESP32 chưa vào Download Mode / Sync failed

Giữ BOOT → nhấn RESET → thả RESET → thả BOOT, rồi bấm kết nối lại. Một số board rời không có DTR/RTS nối đúng chân nên auto-reset không hoạt động — bắt buộc phải làm thủ công.

Permission denied / không có quyền USB Host

Trình duyệt không cho phép trang web truy cập trực tiếp /dev/bus/usb. Đây là giới hạn bảo mật của hệ điều hành, không thể bỏ qua từ JavaScript. Nếu Web Serial báo lỗi này liên tục dù đã chọn đúng thiết bị, hãy thử fallback bên dưới.

Verify failed

MD5 đọc lại từ flash không khớp file gốc. Thường do cáp kém chất lượng gây lỗi truyền ở tốc độ baud cao, hoặc mất kết nối giữa chừng. Thử lại với cáp tốt hơn; không dùng firmware nếu verify vẫn thất bại.

USB bị rút ra giữa chừng khi đang flash

Không tự ý rút cáp khi thanh tiến trình đang chạy — flash dở dang có thể để bootloader ở trạng thái không nhất quán. Cắm lại và làm lại từ bước Xoá Flash.

Trình duyệt không hỗ trợ API cần thiết

Web Serial hiện chỉ chạy trên trình duyệt nền Chromium. Firefox Android và mọi trình duyệt trên iOS/iPadOS (kể cả Chrome iOS, vì dùng WebKit) đều không hỗ trợ. Xem trang Kiểm tra để biết chính xác API nào đang thiếu.

Giới hạn thực tế của WebUSB/Web Serial trên Android

  • Chỉ hoạt động trên trình duyệt nền Chromium — không có trên Firefox Android, không có trên bất kỳ trình duyệt nào chạy engine WebKit bắt buộc của iOS.
  • Trang bắt buộc chạy trong ngữ cảnh bảo mật (HTTPS hoặc localhost); mở qua HTTP sẽ khiến navigator.serial không tồn tại.
  • Người dùng phải chọn thiết bị qua hộp thoại hệ thống ở mỗi phiên — không thể tự động kết nối lại ngầm vì lý do bảo mật.
  • Không có quyền truy cập /dev/bus/usb trực tiếp; mọi giao tiếp phải đi qua API do trình duyệt cấp.
  • Một số ROM Android/trình duyệt OEM tuỳ biến (MIUI, EMUI cũ, một số trình duyệt mặc định hãng máy) có thể chặn hoặc giới hạn thêm quyền USB ngoài chuẩn Chromium.

Fallback khi trình duyệt không hỗ trợ

Nếu Web Serial/WebUSB không truy cập được CP2102/CH340 trên máy bạn, công cụ thuần web không thể vượt qua giới hạn sandbox của Android — cần một trong các hướng sau:

  • Android WebView tuỳ biến + USB Host API: đóng gói trang này trong một app WebView, dùng Android USB Host API (native, Java/Kotlin) làm cầu nối tới CP2102/CH340, expose lại cho JavaScript qua addJavascriptInterface.
  • Termux bridge: cài Termux + gói esptool/pyserial, chạy flash bằng dòng lệnh thực tế trên chính điện thoại (vẫn không cần PC, nhưng cần thao tác terminal).
  • ESP Web Tools: nếu firmware đã được đóng gói theo chuẩn manifest của ESP Web Tools và trình duyệt hỗ trợ Web Serial, có thể dùng thẳng công cụ đó thay vì tự viết.
